# Conventions

## Branches

- One branch per working day and repository: `improve/<topic>-YYYY-MM-DD`.
- Later days of the same repository branch from the previous day's branch (stacked pull requests).

## Commits

- Small, focused commits. One logical change each. The repository must work after every commit.
- Conventional Commits: `docs:`, `feat:`, `fix:`, `refactor:`, `test:`, `chore:`.
- Author: Maryam Mahmoudi. No co-author trailers, no session links, no generated-by footers.

## Pull requests

- Describe what changed, why, how to run it, and show figures where useful.
- List blocked items honestly (a dataset that could not be downloaded, a run that was too slow).
- Do not merge without review.

## Repository structure

```
repo/
  README.md
  LICENSE
  requirements.txt
  .gitignore
  notebooks/   numbered lessons: 01_..., 02_...
  src/         reusable code
  data/        download script or README, no large files
  assets/      figures, plus CREDITS.md
  tests/       at least a smoke test
  legacy/      the original files, untouched
  docs/progress/   daily notes
  .github/workflows/ci.yml
```

## Notebook lessons (classroom style)

1. The big question: what problem are we solving and why does it matter?
2. Intuition first, in plain words, before any code or math.
3. A picture or diagram that makes the idea visible.
4. The minimum math, with every symbol explained.
5. Code in small cells, each followed by what happened and what to notice.
6. Check yourself: two or three questions, answers hidden below.
7. Common mistakes.
8. Recap in three bullets and a bridge to the next notebook.

## Images

- Prefer figures generated by our own code.
- Use an outside image only if its license allows reuse. Download it into `assets/` and record author, license and URL in `assets/CREDITS.md` and in the caption.
- Every image has alt text and a one-line caption saying what to notice.
- No copyrighted book or paper figures, logos, or photos of real people.

## Honesty

- Fix random seeds and say so.
- Report only numbers that code actually produced.
- Cite official documentation or papers for factual claims.
- State the runtime at the top of each notebook.

## Hygiene check

The workflow in `.github/workflows/hygiene-check.yml` fails a pull request if any file contains words that must not appear in these repositories. Copy it into every repository listed in the README.
